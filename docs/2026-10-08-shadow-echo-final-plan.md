# 影迹回声视觉与交互最终实施方案

日期：2026-10-08。方向为“城市余响”：保留当前城市、道路、橙衣跑者和深灰蓝界面，让玩家准确理解回声、路线和代际变化。此方案整合两轮 PDF 评审与最终字段核查，作为本次实施和验收依据。

## 目标与保护边界

先完成真实状态到界面的闭环，再通过目标平台画面调整视觉。复用现有流程、三车道标记和存档事务；不改变 AI 决策、关口奖励、晋升资格、赛道坐标、碰撞和胜负判定。好友异步挑战继续使用冻结对手，不训练、不改猜、不晋升本地回声，不更新本地成绩和金币。

保留用户已有修改，不批量暂存、重置或清理，不提交、不推送、不上传发布。现有验证产物不得作为本次通过证据。

## 数据和文案合同

| 信息 | 唯一数据来源 | 表现规则 |
| --- | --- | --- |
| 本关收益 | PredictionGateSettlement.playerLeadMeters / echoLeadMeters | “反制成功 · 你 +X米”或“它猜中了 · 回声 +X米”；只在对应路线执行成功时出现 |
| 当前领先 | AIShadowRunner.PlayerLead | 正值玩家领先，负值回声领先且显示绝对值；沿用 HUD 的 ±0.05米持平显示区间；显示容差不改变胜负 |
| 关口累计收益 | SingleContractFlow.AccumulatedSignedLeadMeters | 仅用于关口统计，不能代替当前实际领先，不增加一个常驻赛况指标 |
| 本局观察 | SingleContractCalibrationProgress 与已验证本局证据 | 仅描述本局；单项达标不等于全部达标；证据充分且未到终点时提示继续到终点 |
| 可挑战性 | 已保存身份的 RequiresRouteCalibration 等既有入口判定 | 菜单、结算按钮文字与实际进入模式保持一致 |
| 新代生效 | 本局生成结果与存档提交成功结果 | 候选身份或草稿不能当作已保存新代展示 |
| 伤势 | GameManager.CollisionStrikes 与恢复计时 | 恢复结束仍保留累计伤势；1/2 后提示“再受伤即出局” |

反制成功是获得关口优势的方式，不是晋升必要条件。普通挑战获胜后还须满足既有生成条件并保存成功，才有新代生效。观察局必须在本局内取得充分证据并到达终点；未晋升草稿丢弃。

## 菜单和下一局入口

| 状态 | 主信息 | 主按钮和动作 |
| --- | --- | --- |
| 无回声 | 你的跑法，会成为下一局的对手；跑到终点并留下足够的动作与选路 | 开始第一局，进入观察 |
| 有回声但路线记忆不足 | 第N代回声仍保留；这局重新观察动作与选路，满足条件后更新 | 继续观察，实际进入观察 |
| 回声可挑战 | 第N代回声；简述已保存路线倾向，目标为赢下本局 | 挑战第N代回声，实际进入挑战 |
| 好友挑战已准备好 | 挑战好友的回声；本局不影响你的回声成长 | 开始好友挑战，保留异步上下文 |

主菜单标题置左上，状态卡置左下，横屏宽度以安全区约三分之一为起点，保证道路中心和角色可见。竖屏采用底部卡片，不机械沿用横屏宽度。只保留一个主行动按钮，设置和跑者为次级操作。有有效报告内容才显示报告入口。

## 赛中 HUD 和教学

观察局常驻终点、伤势和简短本局观察状态。当前局可显示真实动作和选路进展；详细阈值和全部不足项放入详情，主要缺口优先提示。菜单不得暗示“下一局只补一次即可”。

挑战局常驻终点、当前实际领先和伤势。预测仅在真实活动关口按生命周期显示。首次操作提示和三路图例保留，确认教学进展后收起，设置中可重看。异步模式不得出现学习、改猜、升级提示。

预测路线为方框，反制路线为三角，中立为双线；三种含义同时可辨。非预测路线不自动构成反制；反制需对应路线且执行成功。即时增益与常驻当前领先分开显示，前者不能覆盖后者的数据来源。

## 结算和报告

对局结果、身份生成、提交结果和下一局入口分别保存为事实，不通过玩家文案反推业务状态。

| 结果 | 结算内容 | 下一步 |
| --- | --- | --- |
| 成功更新且新代可挑战 | 对局输赢与第N+1代生效，旧记忆、本局证据和新记忆 | 挑战新回声 |
| 成功更新但新代路线不足 | 新代已生效，路线倾向尚未稳定，不伪造确定偏向 | 继续观察 |
| 获胜但未生成下一代 | 明确赢了本局，旧回声保留，列出可证实的生成不足 | 根据当前保存身份决定再挑战或观察 |
| 挑战失败 | 本局结果、真实关口统计、旧回声保留 | 再次挑战当前回声 |
| 观察不足或提前结束 | 本局未形成新回声，展示主要实际不足和详情 | 重新观察 |
| 保存失败 | 保留真实输赢，明确新代未生效；不宣称全部结果均未保存 | 返回菜单，入口由当前有效保存身份决定 |
| 好友异步 | 真实输赢和挑战结果；不影响本地成长和纪录；云上传状态单独呈现 | 返回或重赛同一冻结挑战 |

“此前”使用本局开始时的身份快照，“本局”使用本局已结算证据，“之后”只使用成功提交的新身份。不得在提交后把当前身份同时用作前后两代。局内报告可以显示真实未保存过程统计，但必须区分“本局发生”与“已写入下一代”。

报告历史后置，若实施，应独立定义版本、容量上限、run/identity 去重键、清理与迁移、空状态以及保存失败语义；不得因一个列表需要而改变身份晋升事务。

## 交付顺序

### 第一批 状态和界面闭环

补齐唯一状态映射、结算分支及下一局实际路由；分开关口增益与实际领先；保留真实本局观察进度、伤势和首次提示；缩小菜单并实现最小横竖屏安全区布局。更新相关测试，尤其覆盖获胜未晋升、提交失败、新代路线不足、近零领先和异步隔离。

出口：相关测试通过；没有虚假累计、错误代数或按钮模式错配；实际菜单、观察、挑战和结算可运行。

### 第二批 路面与回声试验及验证

复用 TrackManager 调整三路提示，在当前场景试验雾蓝和轮廓。允许试验版本先实现，目标平台验证后定稿。第二批验收需要的最低竖屏、低画质和微信支持必须在本批具备；不等待第三批才提供必要运行条件。

出口：录制菜单到结算及并排、前后遮挡、阴影、高速关口；校验所有车道位置、预测更新、取消和回收；WebGL及可获得的目标移动环境运行证据；测试与性能结果独立报告。

### 第三批 依据证据扩展

轮廓方案仍无法满足辨识要求时再加入短残影。完善竖屏和画质档位，检查减少动态效果和色觉区分。报告历史独立评估与实施，不依赖雾蓝视觉的技术通过条件。基础证据不充分时优先补证，不用更多特效掩盖问题。

## 验收协议

代码与测试、构建产物、实际启动、运行画面、真人理解及目标设备性能分开记录。使用本次唯一日志和结果目录，保留文件、命令、退出码和结果摘要。

- 菜单行动：5名未读方案者观看3秒后，至少4名说对下一步。
- 三路语义：首次关口教学后，至少4名正确区分预测、反制和中立。
- 回声辨识：并排、交叠、阴影和高速素材中，每种至少4名分清双方；不能将代理检查冒充真人测试。
- UI遮挡：真实横竖屏及安全区视图中，关键角色、障碍和路线可辨。
- 性能：同设备、同画质、同种子或可复现路线，固定预热与采样窗口，前后各3次。平均帧时间上升不超过10%，1% low FPS下降不超过10%，并记录原始数据和持续卡顿。1% low使用最慢1%有效帧时间均值换算FPS并固定口径。相对门槛之外记录平台目标帧率和绝对表现，不把原本卡顿的基线判为流畅。
- 生命周期：连续运行、退出、失败、重试和身份切换后，无陈旧反馈、串代或异步本地污染。

真人、手机或微信登录验收如需用户参与，先完成所有可自动执行的工作并提供可运行版本与具体步骤；不得将缺失验收标为通过。
