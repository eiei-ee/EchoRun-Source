# 2026-09-23 菜单与好友挑战 UI

当前实施见 [整体视觉重做](2026-09-23-visual-system.md)。本文件保留被否决方案的历史记录。

用户将当前工作切换到 UI 和色彩美术，云部署、套餐和 HTTPS 托管工作暂停。

**设计状态：上一版视觉已被用户否决，不作为美术验收通过或发布候选。** 用户认为暖白卡片与跑步插画的方案不好看。后续先重新检查整屏构图与《影迹》现有城市追逐题材的一致性，制作独立方向稿；以下技术验证仅说明功能与布局检查通过，不代表用户接受了视觉设计。暂停该版预览交付与上传。

## 视觉与交互

- 暖白 `#FFF7EC` 背景、深蓝墨 `#173F50` 正文、珊瑚橙 `#F26D4E` 主操作、湖蓝 `#187B96` 导航和青绿成绩背景。
- 主菜单沿用已有城市跑酷画面，以浅色信息区、橙色开始按钮重新建立阅读顺序。游戏内 HUD 和场景光照未改色。
- 好友挑战采用正式 Prefab：跑者插画、影子代数、固定跑法说明、按状态出现的发布/分享/重试，以及固定在底部的挑战操作。
- 挑战榜独立页面，以逐行成绩取代长文本；本人突出显示。空态、加载、失败、新用户无影子各有说明。
- 插画由内置 image_gen 生成，完整提示词和原图来源记录于 `ArtSource/UI/EchoChallengeDuo.md`。运行时导入限制 1024 像素，保留比例、关闭 mipmap 和 CPU 读写。
- 菜单与挑战界面的主色取自共享 `EchoRunUITheme.Menu*`。外部显示名禁用富文本。排行行对象复用，数量上限沿用云服务 top-50。

## 稳定性

没有改变玩法结算、AI 学习、身份进化、云协议或存档格式。
遮罩是不透明可命中的 UI，卡片间空白也能发起滚动；打开时接管焦点并暂停底层 UI 的键盘交互，关闭/销毁时恢复。
新邀请通过 invitation key 切换页面，旧榜单不能冒充新影子；上一次结果只在相符上下文展示。
加载顺序验证发现并修复菜单安全区初始化早于 MenuPanel 创建时的空引用。
